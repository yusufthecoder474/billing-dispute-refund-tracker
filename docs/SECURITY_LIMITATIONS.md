# Security choices and limitations

Spring Security authenticates seeded BCrypt credentials using a server session. Session cookies are HttpOnly and SameSite=Lax. Secure defaults to true outside local/test profiles; local HTTP deliberately disables it. Do not use the local profile for a real public deployment. Sessions time out after 30 minutes and are invalidated on logout; login uses Spring's session-fixation protection. There is no client role header.

GET /api/auth/csrf establishes a session and returns a masked CSRF token and header name. The client sends that token for every POST, including login and logout. Authentication changes invalidate the cached token; the next write obtains a new one. The session cookie remains inaccessible to JavaScript. Spring's CSRF filter protects requests before controller execution. A malformed/missing token can therefore return 403 before a missing session would otherwise produce 401. No cross-origin API access is configured; Vite uses a same-origin proxy.

Customer ownership and assigned-support checks live in DisputeService, not only in buttons. Managers alone can assign and decide. ReportingController has server method authorization. Password hashes are never serialized. Validation rejects invalid enum values, excessive precision and invalid identifiers. Money is BigDecimal. SQL reports bind timestamp parameters. React renders descriptions as text. The CSV writer quotes fields, escapes embedded quotes and prefixes values with spreadsheet formula/control prefixes; reports contain aggregates only, not customer text.

The audit API is read-only. AuditRepository exposes no update/delete operation, but the database account and administrators can modify data. There is no cryptographic signing or tamper-proof audit storage. Local database credentials are for synthetic demonstrations. Migration and runtime accounts should be separated for an actual deployment.

Known omissions: rate limiting, account lockout, MFA, registration, password reset, identity provider integration, session replication, backup automation, legal retention rules and penetration testing. Security is educational and not production-certified. Public deployment requires HTTPS, private real credentials, secret management, dependency review and an appropriate data handling policy. This repository must contain only fictional records.
